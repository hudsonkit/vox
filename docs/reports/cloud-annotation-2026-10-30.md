# Cloud annotation verification, 2026-10-30

## Scope

PR #38 adds Swift file annotation for `elevenlabs:scribe_v2` and
`deepgram:nova-3` behind `annotate.file`, plus `annotation.models` inventory.
These are explicit cloud uploads with request-scoped vendor credentials, not
native dictation fallback. Native Unified streaming and Parakeet batch are
unchanged. Talkie owns its adapter; no Talkie files changed here.

The provider uses the existing in-process Swift `AnnotationProvider` contract.
It does not add an external ASR provider process or alter the Rust ASR protocol.

## Reproduction

On macOS with Xcode Swift 6.2 or newer and Python 3:

```sh
xcrun swift build --package-path swift --product voxd --jobs 3
python3 scripts/test-private-annotation.py
xcrun swift test --package-path swift --jobs 3
bun test packages/client/test packages/cli/test packages/web-client/test
bun run docs:check
```

The fixture test builds a fresh independent consumer importing only `VoxClient`.
It launches the actual debug `voxd --private` in an isolated temporary Vox home.
Two clients discover its autogenerated 0600 capability without a socket or token
in their environments. A loopback HTTP server asserts vendor requests and returns
synthetic fixtures matching the vendors' documented response shapes.
No paid endpoints or real account credentials are used.

| Deepgram routing | Raw WAV bytes, `model=nova-3`, `diarize_model=v2`, utterances, language detection, `Authorization: Token` |

| Non-retention | Keyless request after a successful upload fails before HTTP; neither daemon home nor logs contains any fixture credential |
| Scribe evidence | Two speech words, one separate laughter event, original speaker IDs, raw logprob, null confidence, detected language; actual WAV duration fallback |
| Deepgram evidence | Decimal-string speaker IDs, returned word/speaker confidence, missing scores null; vendor duration/model revision preserved |
| Missing fields | No fabricated vendor model/request ID, scores, language, timings or acoustic VAD. Unsupported and unavailable field lists are separate |

| Cancellation | Cancelling client A's task closes its private connection and outgoing HTTP connection; client B remains usable |

The private fixture observes exactly seven expected uploads. Core/provider tests
also cover malformed/missing intervals, unknown token types, score nullability,
header-injection rejection, bounded responses, invalid JSON, credential allowlists,
service forwarding/telemetry and reserve/attach/disconnect ownership races.

## Limits

- This verifies the local transport and vendor contracts, not live vendor access,
  diarization/transcription accuracy, real meetings or account-specific model access.
- Scribe supplies log probabilities, not calibrated word confidence. Deepgram
  audio events and language confidence are unsupported. Missing vendor fields
  stay absent/null, with availability metadata.
- Derived speaker spans are word coverage, not acoustic VAD. Utterance transcript
  confidence is not a speaker probability.
- Duration is vendor evidence or readable local media metadata, not billed duration.
  If neither exists, annotation errors rather than inventing a required metric.
- Input <=2,000,000,000 bytes; response <=4 MiB; encoded result <=8 MiB; two active
  uploads maximum. Unknown/oversized responses fail explicitly.
- Cancelling an upload cannot guarantee vendor cancellation, refund or retention.
  The caller must obtain cloud-upload consent. Vendor default retention applies;
  Vox does not request or promise enterprise zero-retention features.
- No release, merge, paid call, launchd edit or installed-daemon replacement occurred.

See [the runtime contract](../runtime.md#file-annotation) for the complete request,
result and credential semantics. Vendor source shapes:
[ElevenLabs conversion API](https://elevenlabs.io/docs/api-reference/speech-to-text/convert),
[Deepgram prerecorded API](https://developers.deepgram.com/reference/speech-to-text/listen-pre-recorded).
